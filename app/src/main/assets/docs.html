Phone API

Use SMS, contacts, calendar, notifications and device controls through your phone.

Device statsOpenAPI definitionRoutesSend an SMS

This guide is public on the API listener. Device information and SMS routes require authentication. There are no third-party scripts or remote assets.

Authentication

For the browser login, use username api and your saved API key as the password. A random key is generated on first launch; copy it from Phone API. It stays saved across restarts and updates until you change it in Phone API.

For API clients, send Authorization: Bearer YOUR_KEY. Saving a new key takes effect immediately.

export PHONE_API='http://your-phone:8765'
export PHONE_API_KEY='your-saved-key'
curl -H "Authorization: Bearer $PHONE_API_KEY" "$PHONE_API/health"

The hostname works when Tailscale MagicDNS is available. You can also copy the current Tailscale IP URL from the Android app.

Routes

GET /
Device stats in your browser. Uses the browser login above.
GET /docs · GET /openapi.json
This guide and an OpenAPI 3.1 definition. No key required. Import the definition into an API client or Swagger viewer.
GET /health · GET /stats · GET /device/status
JSON stats: device, battery, permissions, addresses, active listeners, SIMs and SMS request counts.
GET /health/live
Returns status and service uptime when the listener is responding.
GET /health/ready
Returns 200 when SMS permissions, active SIMs and the Tailscale listener are ready; otherwise 503 with setupNeeded.
GET /sms/subscriptions
Active SIMs with subscriptionId, name, carrier, slot, embedded and defaultSms. Requires SIM permission.
GET /sms/messages?limit=20&after=0
Inbox messages, newest first. limit: 1–100. after: exclusive Unix timestamp in milliseconds. Each message includes id, from, text, receivedAt and subscriptionId. Requires SMS reading permission.
POST /sms/send
Submit an SMS. Requires SMS sending permission, JSON and an Idempotency-Key. See below.
GET /sms/requests/{id}
Check a submitted request: submitting, submitted, sent or failed. Also includes parts, sentParts, createdAt, errorCode and subscriptionId.

Find a contact’s messages

Supply an E.164 number. The API normalises national-format numbers using the network/SIM country, then the device locale, then GB. Override this with region=GB if needed. Matching uses the full normalised number, not a suffix.

curl --get "$PHONE_API/sms/messages" \
  -H "Authorization: Bearer $PHONE_API_KEY" \
  --data-urlencode 'number=+447700900000' \
  --data-urlencode 'region=GB' \
  --data-urlencode 'limit=50'

With a number, the default box=all includes incoming and sent SMS. Without a number, it defaults to box=inbox. You can set box=inbox, sent or all. Results include direction, address and numberE164. Non-phone senders have a null normalised number. Encode + as %2B in direct URLs.

after and before are exclusive millisecond timestamps. This is a bounded view, with at most 100 messages per request; timestamp-only paging can skip messages that share a boundary timestamp. SMS stored by your SMS app is available; MMS and RCS are not.

Send an SMS

First discover your SIM IDs. IDs can change if a SIM is replaced.

curl -H "Authorization: Bearer $PHONE_API_KEY" \
  "$PHONE_API/sms/subscriptions"

Set subscriptionId to the SIM you want to use. If omitted, Android's default SMS SIM is used; if there is no default, the API returns 409.

This example sends a real SMS when you supply a real recipient. Replace the example number and SIM ID before running it.

curl -X POST "$PHONE_API/sms/send" \
  -H "Authorization: Bearer $PHONE_API_KEY" \
  -H 'Content-Type: application/json' \
  -H 'Idempotency-Key: my-message-000001' \
  --data '{"to":"+447700900000","text":"Hello from my agent","subscriptionId":1}'

to must be an international number beginning with +. text accepts 1–2,000 characters. Request bodies are limited to 8,192 bytes; send Content-Length rather than chunked encoding.

The response is 202 Accepted with an id. Check that request:

curl -H "Authorization: Bearer $PHONE_API_KEY" \
  "$PHONE_API/sms/requests/REQUEST_ID"

sent means Android reported every SMS part as sent. It does not confirm delivery to the recipient. Multipart messages may incur multiple SMS charges.

What is an idempotency key?

It labels one SMS send attempt. It is separate from your API key. If a request times out, repeat it with the same key and body: the phone returns the existing result without sending twice. Use a new key for each new message. A UUID is a convenient key.

# Create once for this message; keep it for any retry.
export SMS_REQUEST_KEY="$(uuidgen)"
# Send it as: -H "Idempotency-Key: $SMS_REQUEST_KEY"

Safe retries

Use a unique Idempotency-Key of 16–128 letters, digits, underscores or hyphens for each new message. Retry with the same key and exactly the same body to get the existing request without sending again. Reusing it for a different message returns 409. There are no automatic SMS retries.

Additional routes

GET /capabilities
Permissions, notification connection, vibrator availability and default number region. Missing optional permissions do not stop the SMS API.
GET /device/battery · GET /device/network
Charging state, temperature, voltage, battery saver, device idle state, network transports, metering and actual IP addresses. Battery status and health use Android BatteryManager integer values.
GET /contacts?q=Alice&limit=20
Contact phone entries, with id, name, number and numberE164. Multiple numbers produce multiple rows. Also accepts number and region. Requires contacts permission.
GET /calendar/calendars
Calendars with IDs, names and account details. Requires calendar permission.
GET /calendar/events?from=…&to=…&calendarId=…
Appointments, including recurring instances. from/to are Unix milliseconds; defaults to now through seven days. Maximum range: 31 days. Optional calendarId and limit (1–100, default 50).
GET /location
Last known position. Check available and ageSeconds; cached positions can be old. Requires location access, plus Allow all the time when Phone API is not visible.
GET /location?fresh=true&timeoutSeconds=10
One location request, lasting at most 1–15 seconds. Android may return a recent fix. No fix gives available:false and location:null. There is no continuous tracking. Allow at least 20 seconds for the client timeout.
GET /notifications?package=com.example.app&limit=20
Current notifications, newest first, with package, key, title and text. Requires special notification access. Android can redact sensitive content; Phone API’s own notifications are excluded.
POST /device/ring
JSON {"durationSeconds":5}, range 1–30. Requests the default ringtone; silent mode, volume and Do Not Disturb can affect audibility. DELETE /device/ring stops it.
POST /device/vibrate
JSON {"durationMs":500}, range 1–5,000. Requires a device with a vibrator.

Webhooks

Configure the destination on the phone under Webhooks. Delivery is off by default. Save a URL, optionally set a separate Bearer token, choose Incoming SMS and/or notification posts/removals, then enable delivery. Notifications are forwarded only for the package names you explicitly enter.

GET /webhooks shows configuration, queued/delivered/dropped counts and the last error. Tokens are never returned. PUT /webhooks accepts url, enabled, token, events and packages. Omit token to keep it for the same URL; an empty token clears it. Changing the URL clears the old token and queue. Disabling delivery also clears queued events. A request already in flight cannot be recalled.

{
  "url": "http://your-agent:8080/phone-events",
  "enabled": true,
  "events": ["sms.received", "notification.posted", "notification.removed"],
  "packages": ["com.example.app"]
}

Use HTTPS for public destinations. HTTP is supported for private networks, including Tailscale. Redirects are not followed. POST /webhooks/test queues a synthetic test without an SMS. Its delivery status appears in GET /webhooks.

{"id":"event-uuid","type":"sms.received","createdAt":1234567890000,
 "data":{"from":"+447700900000","numberE164":"+447700900000",
         "text":"Hello","receivedAt":1234567890000,"subscriptionId":1}}

Incoming SMS is event-driven and needs Receive SMS permission. Notification data uses the same fields as /notifications. Every POST has X-Phone-API-Event-ID and X-Phone-API-Event headers. The receiver must acknowledge with a 2xx response and deduplicate by event id: delivery is at least once. Android schedules retries with backoff; delivery may wait during Doze or network loss. Keep receiver processing quick.

Pending events persist across process restarts. The queue holds at most 500 events for seven days; expired or oldest overflow events are dropped and counted when the queue is processed. Stop API pauses capture/delivery. Restarting resumes pending events. There is no idle network polling.

Errors and background running

Errors have a JSON error field: 400 invalid input, 401 missing/wrong key, 403 missing phone permission, 404 unknown route or request, 405 wrong method, 409 conflicting request or missing default SIM, 411 missing Content-Length, 413 oversized body, 415 wrong content type and 503 not ready.

Enable Run API in the Android app. It uses a foreground service with a quiet notification and recovers after process interruptions, app updates and reboot when Android permits. Stop API disables automatic recovery. Android force-stop requires reopening the app.

The service has no idle polling or wake lock. Android sleep behaviour and Tailscale availability can still affect reachability. This version does not provide voice notes or Android Auto controls.
